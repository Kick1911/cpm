# AGENTS.md

C99-free, `-std=c89 -pedantic -Werror` C CLI. CPM is a project scaffolder/build tool that generates new C projects; this repo is also a self-hosting example of one (its own `Makefile`/`config.mk` mirror `share/templates/`).

## Commands

- `make` — build debug binary with ASan/UBSan + `-DLOG_LEVEL=1`.
- `make test` — build all `tests/test_*.c` and run each under `valgrind --error-exitcode=1 --leak-check=full`. **Requires `make clean` first**; default-build `.o` files are ASan-instrumented and fail to link with `test_compile`'s different flags.
- Single test — `make clean && make tests/test_render.out && valgrind --error-exitcode=1 --leak-check=full ./tests/test_render.out`.
- `make prod` — static release build (`-O3 -static`). CI parity: `CC=clang make` and `CC=musl-gcc make prod` must pass.
- `make clean` removes binary, all `.o`/`.d`/`.out`, `dist/`. `make release` tags and pushes `v${VERSION}` (VERSION in `project.mk`).

## Gotchas

- `dependents/` and `src/project_map.h` are gitignored and generated. Fresh builds download deps (incl. the `unitest` test header) from the GitLab generic registry via curl — **network required**; `make test` also needs `valgrind`.
- `src/project_map.h` is generated by `cpack.py` from `share/templates/*` (path separator `#`, `$0`/`$1` args) + `share/metadata.json`. Editing a template requires a rebuild to regenerate; files marked `"type": "system"` in `metadata.json` overwrite user files on `cpm update`, others are skipped.
- Strict warnings with `-Werror`: no `//` comments, no C99 declarations, no implicit conversions (`-Wconversion`). Must compile clean under gcc and clang.
- Subcommands are C files in `src/components/` registered in `src/components/components.h` via `CPM_APP_FUNCTION(name)` / `CPM_REGISTER_APP(name)`; dispatch table is consumed by `main` in `src/cpm.c`.
